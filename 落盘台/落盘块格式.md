# 落盘块格式（AI 唯一要产出的机器可读物）

审查报告的第六项就是它。审查工作台生成的 prompt 里已经带了这份规范，
这里留一份单独的，方便贴给别的模型、或者自己手写。

```
<<<落盘>>>
@修订 1 | 第7.2条
原文：甲方应在收到发票后15日内付款
改为：甲方应在收到发票且发票经审核无误后30日内付款
理由：付款起算点不明确，审核期未约定
@删除 2 | 第9.4条
原文：，并按日万分之五支付违约金
理由：同一违约行为重复约定违约金
@批注 3 | 第3.1条
锚点：甲方应在收到发票后15日内付款
批注：请确认审核时限。
理由：属商业判断，需经办人决策
@新增 4 | 第9条之后
锚点：本合同一式肆份，甲乙双方各执贰份。
正文：9.5 因不可抗力导致本合同无法履行的，双方互不承担违约责任。
理由：缺不可抗力条款
@删段 5 | 第11.3条
锚点：甲方有权索扣履约保证金
理由：全文未设履约保证金，该条无所依附
<<<落盘完>>>
```

## 五种条目

| 类型 | 干什么 | 必填 |
|---|---|---|
| `@修订` | 把一小段原文改成另一段 | 原文、改为 |
| `@删除` | 把一小段原文整串删掉 | 原文 |
| `@批注` | 在某串原文上挂一条 Word 批注 | 锚点（或位置）、批注 |
| `@新增` | 在某一段之后整段新增 | 锚点、正文 |
| `@删段` | 整段删掉 | 锚点 |

头行：`@类型 序号 | 条款位置`。序号和位置都可省，但给了更好——位置用来在同一句话
全文出现多次时消歧。字段名固定：原文／改为／锚点／批注／正文／理由／第几处。
冒号全角半角都认，行首的 `-` `*` 列表符也认。

## 十条规矩

1. 「原文」「锚点」必须是来件里逐字照抄的一小段，标点一起抄。
2. 空格、全半角、弯直引号的差异程序会归一；但不许改字、不许省略、不许用「……」代替中间。
3. 「原文」不得跨自然段。一句里改两处就写两条。整段替换拆成「删段＋新增」。
4. 抄得越短越好定位，只要在该条款里唯一即可。
5. 「改为」写改完之后那一小段的完整文字。程序自己算最小改动，你不必只写变化的字。
6. 「批注」≤40 字，一条只讲一个问题；说理写在「理由」里，不进 Word。
7. 「正文」多段就分行写，程序按条款号开头判断分段。
8. 数字、金额、名称照抄来件写法。
9. 块里不写表格、不写 markdown、不加代码围栏、不写旁白。
10. 目录、页码、页眉页脚只批注不修订；表格内、图片内的问题不进落盘块，另列一项留给人工。

## 程序会怎么对待你的文字

- 「原文」跟来件对得上 → 直接落。
- 只差空格/全半角 → 归一后按**来件里的原样**定位（写进文件的是来件的字，不是你的字）。
- 差一两个字 → 按相似度定位，标「请核对」，等人看一眼。
- 差太多 → 标「找不到」，给出最像的几段让人指认。
- 抄错到「其实没有改动」 → 直接跳过并说明，不会往文件里塞一个空修订。
- 落在来件既有修订块里 → 拒绝叠改，提示先与经办人确认。
- 两条改到同一处 → 拦下，提示合并。
