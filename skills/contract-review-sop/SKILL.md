# 合同／文书审查落盘 SOP（自主执行）

## 这条流水线交付什么

**默认交付物只有一个：来件本身，带上本次的修订痕迹与批注。**

- 不默认落地报告文件——审查报告写在聊天回复里，用户要文件再说；
- 不重排、不美化、不整篇转换、不动目录页码页眉页脚。

**这条流水线不需要人点一下。** 判断标准（138 张规则卡）和落盘程序都在本技能里：
`rules/` 是规则库，`scripts/assemble.py` 按本件情况装配当次指令，
`scripts/oneshot.py` 把结论落进 Word。落盘台界面上人能做的每件事（指认段落、把修订降级为批注、
就地改原文、跳过、导出落盘块），命令行都有对应参数。你自己判断、自己收敛、自己交付；
只有真判断不了的，才列出来交给经办人。

慢的从来不是脚本，是来回次数。**整张清单一次跑完**（.docx 约 1 秒、.doc 约 4 秒），
不要一条修订跑一条命令，更不要自己写 XML。

## 第 -1 步 · 先确认署名是配好的（只做一次）

```bash
python3 $S/config.py
```

署名、缩写、工作时段、交付文件名后缀、我方默认立场，全部来自工具包根目录的 `配置.json`。
**如果它打印出「署名仍是默认占位值」，先让用户填**——署名会写进交付件的每一处修订与批注，
默认值发出去就是错的。用户当次另有交代的，用 `--author` / `--initials` 覆盖，不必改配置。

## 固定口径（用户当次另有交代的从其交代）

| | |
|---|---|
| 署名 | 取 `配置.json` 的「署名」与「署名缩写」。来件里第三方（客户、对方律师、前手）的修订与批注**一个字不动** |
| 时间线起点 | **用户把文件发给你的那一刻**（北京时间）。落在配置的工作时段内，默认不落周末 |
| 时间写法 | 北京时间钟面值，绝不折算 UTC（脚本负责，你只给起点） |
| 交付文件名 | 来件名 + 配置的「交付文件名后缀」，扩展名与来件完全一致（.doc 进 .doc 出） |
| 交付位置 | 来件所在文件夹；同时把文件发到对话里 |
| 批注文字 | ≤40 字，一条只讲一个问题，问句或「提请关注」式；说理写进报告，不进 Word |

## 脚本在哪、在哪台机器上跑

`$S` ＝ **本技能目录下的 `scripts/`**（和你正在读的这份 SKILL.md 同级），自带引擎、核心、装配器
与交叉引用脚本，不依赖别的技能。只有一件事要先想清楚：**脚本必须和来件在同一侧**。

- 来件在你自己的工作环境里（对话附件、你下载到本地的文件）→ 直接 `python3 $S/oneshot.py`；
- 来件在用户机器的共享文件夹里，而你只能通过桥接读写 → 在用户机器上跑工具包里「落盘台」的
  `一键落盘.py`（与 `$S/oneshot.py` 同一份代码，参数一样），就地读写；或者把来件取到自己这边
  跑完再把交付件写回去。**别在两边各留一份来件。**
- `.doc` 来件要靠 LibreOffice 进出格式：`--inspect` 会告诉你这台机器有没有。

## 第 0 步 · 先看来件（1 秒）

```bash
python3 $S/oneshot.py --input "来件.docx" --inspect --json -
```

给你四件事：后缀、段落数与表格内段落占比、来件既有第三方痕迹的作者与处数、本机有没有 LibreOffice。

**硬指标：命中任一条，就不由你改文件，改为只交落盘块纯文字，让人在落盘台上手落。**

1. 来件是 `.doc` 且两侧都没有 LibreOffice；
2. 一次跑完并自动收敛之后，仍有 **1/3 以上**条目落不上；
3. C0–C7 体检任一 FAIL（此时程序本来就不出文件，别硬发）；
4. 过半段落长在表格里（表格内的问题按本 SOP 归人工）；
5. 用户明确说了「只要文字，我自己落」。

来件已带第三方修订/批注**不是**退回理由——那是常态，脚本只叠加不改动，C7 会逐条核对。

## 第 1 步 · 认清这是什么件，装配本次专用的审查指令

**规则不是一次全上。** 138 张卡按「通用核 ＋ 情形包 ＋ 类型包」装配，只把用得上的带进场——
全量套用会让你在不适用的条目上浪费判断力，还会把不该提的意见提出来。

```bash
python3 $S/assemble.py --list --json -                 # 有哪些包、各自什么时候装
python3 $S/assemble.py --scan "来件.docx" --json -      # 机械扫线索 + 强触发 + 多主体检测
```

`--scan` 只数关键词：告诉你正文里出现了「补充协议」「村民委员会」「中标通知书」「美元」这类词多少次，
以及哪些规则卡的「在文本里看到」命中了。**它不做判断**，判断是你的事：

1. **合同还是非合同文书**（`--mode contract|doc`）。文书再分章程 `zc`／决议 `jy`／函件 `hj`／
   制度 `zd`／报审表 `bs`／其他 `qt`。
2. **A 类还是 B 类**（`--track A|B`）：我方制式模板（默认信任正文，怀疑填进去和改过的内容）
   ／对方模板、双方自拟、政府或格式文本（不预设任何条款可信）。
3. **类型包最多一个**（`--type T1…T10`）：T1 工程施工与总承包、T2 设备采购与技术协议、
   T3 技术与专业服务、T4 租赁、T5 投资与框架协议、T6 金融借款、T7 公司治理、
   T8 函件与承诺函、T9 安全生产协议、T10 结算变更报审。
   **没有对得上的类型包就不装**（`--type` 留空），只用通用核＋情形包；
   这说明你这个行业还缺一个包，办法见工具包根目录的 `CLAUDE.md`。
4. **情形包按交易实际装**（`--situ S1,S3,…`）：我方多主体、框架＋项目两层、补充变更终止、
   涉政府或村集体、涉招投标、对方模板、涉外币、涉不动产在建工程。拿不准就装上——每张卡都带「例外」，
   写明什么情况下这条不适用、照套会怎么误导。
5. **我方是谁**用 `--org` 写一句（如「一家制造业集团」「某医疗器械公司」），
   它决定模型代入谁的立场；不给按「我方」。经办人给的交易背景原样写进 `--note`。

```bash
python3 $S/assemble.py --mode contract --track B --type T1 \
  --scan-input "来件.docx" --situ S1,S3,S5 \
  --org "一家制造业集团" --role 发包人 \
  --note "我方为发包人，一侧 3 家项目公司；本件是施工补充协议；已履行招标" \
  --file "来件.docx" --out 本次审查指令.md
```

**`--scan-input` 是默认动作，别省**：它把扫描到的**强触发情形包自动装上**（多甲方、涉政府或
村集体、涉招投标、涉外币、涉不动产、补充变更终止、框架两层），并顺手把交叉引用清单提出来，
指令顶部会写清楚自动装了什么、依据是哪几个词。

**装配宁滥勿缺。** 少装一个包＝那一整包的实战硬伤全漏掉（例如漏掉 S1，就漏掉「分别结算、
分别开票、各甲方不承担连带清偿责任」这条**必补条款**、签署栏分设、管辖落到具体主体、
价格口径、设备归属、份数六条）。多装一个包只是多读几条规则，而且每条都带「例外」告诉你
何时不适用——不适用的写进【清单证伪】即可。**要排除某个强触发包，必须用 `--no-situ` 明写，
并在报告里交代理由**，不能默默不装。

出来的就是本次专用的审查指令：立场与分类、修订 vs 批注的分界、批注口吻、克制原则、
**装配到的那些规则卡（每条带"在文本里看到什么／怎么写批注／什么情况下不适用"）**、
确定性九查、资信与跨文件一致性、背景卡、十六项输出格式、落盘口径（含落盘块规范）。
**接下来照它执行**——它就是本次的执行标准。

- 审查过程中想查某条规则的原话：`python3 $S/assemble.py --card G4`
- 用户在《审查工作台》（工具包 `工作台/审查工作台.html`）里改过规则、存成 rules.js 的：
  `--rules 那个文件`，两边口径就还是同一套。
- 批注该怎么写，看装配出来的规则卡——每张卡的「怎么写批注」就是可直接照用的措辞，
  138 张卡合起来就是一份批注语料。写批注前扫一眼本次装配到的那几条即可。

## 第 2 步 · 机械前置：先把不用脑的做完

1. **交叉引用（每件必跑，不是可选项）**：`--scan-input` 已经提过一次；没提的补跑
   `python3 $S/xref/extract_index.py "来件.docx" -o /tmp/xref.json`
   拿到编区结构、条号索引、引用清单，再按 `references/交叉引用判定规则.md` 逐条核
   存在性 → 层级称谓 → 语义匹配 → 结构合理性。
   - 条号不存在、或唯一正确值可判定的 →【修订】；
   - 通用条款与专用条款同号并存、位阶不明的 →【批注】「请核实第 X 条指向……」；
   - 结论直接写成落盘块条目，不另写一份报告（用户单独要专项报告时才写）。
2. **错别字与衍字（每件必跑）**：`python3 $S/typo.py --input "来件.docx" --emit-block 错别字块.txt`
   （`--scan-input` 已经顺手跑过一次，看指令顶部那行）。扫六类：衍字（「的的」「提交提交」）、
   段内重复长句（复制粘贴没删干净）、易混词与已废止法名（末/未、己/已、既/即、签定/签订、帐/账、
   帐/账、权力义务、法人代表、《合同法》《物权法》…）、大写金额混排、括号不配对、词中空格。
   **错别字属确定性错误，一律【修订】不批注**；脚本出的落盘块直接并进你自己的落盘块一起跑。
   判词表在 `rules/易混词.json`，见到新的错法就往里加一条。
3. **确定性九查里可机械化的项**：空格与勾选、金额验算、单位口径、附件三对照、份数、
   主体名称逐字比对、日期推演、法规真伪。逐项过，命中即处理，不需要法律判断。

## 第 3 步 · 判断：两遍法，清单只是查漏工具

- **第一遍 裸审**：先不看装配出来的规则清单。只带我方立场、交易背景、输出要求读一遍，
  凡是「别扭、读两遍才懂、算不过来、对我方没有对价、机制在时间轴上跑不通」的全记下来。
- **第二遍 补漏**：再打开规则清单，**只做加法**，严禁删除或降级任何裸审发现。
  每条规则后面的「例外」先读，再决定要不要提。
- 【清单外发现】与【清单证伪】两项必答，不得为空、不得答「无」而不给理由。
  清单证伪就是回答：这次装配的这些规则里，哪几条在本件背景下不适用或照套会误导。

判断产出的是**清单**，不是文件。清单没定完就别动手落盘。

## 第 4 步 · 写落盘块

落盘块是你自己的作业计划，也是人能读、落盘台能吃的同一份东西。格式见
`references/落盘与体检.md`（一字不得走样）。五种条目：`@修订`／`@删除`／`@批注`／`@新增`／`@删段`。

抄「原文」「锚点」的三条纪律：**逐字照抄来件、不跨自然段、越短越好定位**。
空格与全半角差异程序会归一，但不许改字、不许用「……」省略中间。

## 第 5 步 · 一条命令跑完（自主模式）

```bash
python3 $S/oneshot.py --input "来件.docx" --block 落盘块.txt --auto \
  --start "2026-09-01T09:20" --json 报告.json --emit-block 实际落盘块.txt
```

`--auto` ＝ `--on-blocked note`（修订落不了刀就降级为批注）＋ `--auto-pick 0.9`（候选相似度 ≥0.9
且明显领先时自动指认）。一个进程做完：解析 → 逐条定位并收窄修订范围 → 自动收敛 → 生成 plan →
批量落盘 → 署名与北京时间 → 打包 → C0–C7 体检 → 交付。

**先 `--dry-run` 试跑一次**（不写任何文件），确认清单全部能锚定，再正式跑。
**体检任一 FAIL 就不出文件，来件本身一个字没动。**

JSON 报告里三样东西是给你看的：`actions`（程序自动做了什么）、`needs_human`（收不住、要你定的条目
及其候选段落）、`checks`（体检逐项结果）。

## 第 6 步 · 自己收敛：一个 patch 文件把决定交回去

`needs_human` 不为空就再跑一轮。决定写成一个 JSON，`--patch 决定.json` 交回去：

```json
{"3": {"kind": "note", "note": "请确认审核时限。"},
 "7": {"src": "更短的一句原文"},
 "9": {"pick": {"para": 132}},
 "11": {"skip": true}}
```

uid ＝落盘块里条目的先后顺序（1 起），不是 `@修订` 后面那个允许重复的序号。

| 程序说 | 你怎么办 |
|---|---|
| 命中 / 请核对 | 直接落。「请核对」是归一化之后定的位，看一眼 `preview` 确认没歪即可 |
| **原文落在来件既有修订块里，下不了刀** | `--auto` 已自动降级为批注，但它写的批注是**占位口径**——用 patch 换成你自己的话（动词开头、≤40 字、一条一个问题）。确实必须以修订形式落的，`skip` 掉并请经办人与对方律师确认 |
| 全文找不到这段原文 | `--search "关键词"` 看来件真实原文 → patch 改 `src`（多半是抄漏、全半角、数字与汉字之间的空格）→ 重跑。来件确实没有这句的，`skip` 并列明 |
| 同样的文字全文多处 | 看 `cands` 的段落原文，够把握就 `pick`；不够把握就 `skip`，别猜 |
| 按原样比对「其实没有改动」 | 你的「原文」抄错了字，重抄；不要往文件里塞空修订 |
| 两条改到同一处 | 合并成一条重写 |

**最多三轮**。三轮之后仍有 1/3 以上落不上，按第 0 步硬指标退回纯文字，
把 `--emit-block` 导出的实际落盘块交给经办人，让他在落盘台上手落。

**拿不准就跳过并说明，不猜着往客户文件里写。**

## 第 7 步 · 交付与回话

把交付件发到对话里；连了本地文件夹的，脚本已经写回来件所在文件夹，说清楚文件名即可。

回复里说这几件事（**报告写在聊天里，不落地文件**）：

1. 审查结论：可用印 / 修改后可用印 / 存在重大风险需退回；
2. **本次装配了哪些包**（一句话即可，让经办人知道你按什么标准审的）；
3. 落盘统计：修订 X 处、批注 Y 条、时间线区间、体检全过；
4. **程序自动改过口径的**（`actions` 里降级为批注、自动指认的），逐条说明，让经办人有机会推翻；
5. 未落盘条目：逐条写明是什么问题、为什么没落、建议怎么处理；
6. 需经办部门确认事项（交易背景、授权文件、待补材料）；
7. 固定收尾：目录及页码未作修改，定稿后请更新目录域；如有条款增删，请同步更新编号与交叉引用。

## 按需的一件事（不主动做）

- **交叉引用专项报告**：用户单独要「核对交叉引用」时，走 `contract-cross-reference-checker`
  技能出分级报告；日常审查里它只是第 2 步的一个前置。

## 用户想改规则卡时（很常见，按这个来）

规则库是这套东西里唯一该长期生长的部分。**用户说"这条规则不对""再加一条""我们行业还有个坑"，
不要只在这次对话里迁就他，要落回 `rules/规则库.json`**——否则下一件又漏。

```bash
python3 $S/assemble.py --card G4          # 先看这条现在怎么写的
python3 $S/查规则库.py                     # 改完必跑：查重号、查孤儿卡、查必填字段
```

改法与字段含义见工具包根目录的 `CLAUDE.md`（那是给你和用户共用的维护手册）。三条要点：

1. **一张卡只讲一个问题**，`sig` 写"在文本里长什么样"（越具体越好，最好是能被眼睛扫到的原句片段），
   `fail` 写"什么情况下这条不适用"——**`fail` 不能省**，没有例外的规则会被照套并产生错误意见。
2. **加卡先归包**：属于哪个情形包/类型包？都不属于且每件都要查 → CORE。
   本行业独有的一类合同没有对应类型包 → 新建一个 `T11`、`T12`，并往 `rules/识别线索.json`
   的 `type` 里加它的触发词。
3. 卡片 id 前缀必须与 `pack` 一致（CORE 包的卡以 `G` 开头），改完跑 `查规则库.py` 会告诉你。

用户在《审查工作台》页面里改卡的，改完让他存成 `rules.js`，再
`python3 $S/抽取工作台.py 工作台/审查工作台.html` 抽回技能，两边口径才一致。

## 铁律

1. **不过体检不交付**：C0–C7 任一 FAIL，停下来修，不许把文件发出去。
   C2 挂＝有改动没被修订标记包住；C7 挂＝动到了别人的痕迹——这两条一律不硬发。
2. **只改该改的地方**：不手写 XML、不重排、不美化、不动样式表与页眉页脚、不改目录与页码。
3. **别人的痕迹一个字不动**：来件既有的修订与批注保留署名、时间、内容；本次痕迹只叠加。
4. **不要整篇 LibreOffice/pandoc 另存**（.doc 进出口那一次由脚本自己做）。
5. **一次跑完**：默认 `oneshot.py --block --auto`；单步模式（prep/apply/stamp/finish）只在批量搞不定时用，
   且改完正文必须重跑 stamp.py → finish.py，否则留下 `PENDING` 署名。
6. **规则按情况装，不全量套**；装了的也要逐条问「这份文件是不是这条说的那种情况」，
   不是就跳过，并写进【清单证伪】。
7. **自动降级要交代**：程序把修订降成批注是为了不卡住，不是替经办人做决定——交付回复里必须逐条说。
8. 表格内、图片内、页眉页脚、目录里的问题，以及需要整体重排或重新编号的，**不进落盘块**，单列给人工。
9. **错别字、衍字、括号不配对是默认动作**：每件必用 `typo.py` 机械扫一遍，扫出来的确定性错误
   直接进落盘块（【修订】），不要留成「请核对错别字」这种批注。肉眼在四十页合同上必漏。
10. **交叉引用是默认动作**：每一件都要跑一次提取、逐条核；报告第九项写明「交叉引用：核了 X 处，
   发现 Y 处」。一处引用都没有的，也要写「全文无交叉引用」，不许略过不提。
11. **装配宁滥勿缺**：强触发的情形包默认装上；要不装就 `--no-situ` 明写并在【清单证伪】说明理由。
12. **体检挂了是脚本的问题，不是文件的问题**：C0 报某个部件 XML 非法（如 `unbound prefix`），
   说明脚本在某条路径上产出了坏结构——去修脚本（可复用于以后所有来件），
   **绝不手写交付件的 XML 去凑**。修完跑一次 `python3 $S/自检.py 某份真实来件.docx`：
   它会造出「没有 commentsExtensible」「没有 people」「整份来件一条批注都没有」等变体，
   把平时跑不到的「新建部件」路径都走一遍，五个变体全 PASS 才算修好。
13. **署名不是占位值**：交付前确认 `config.py` 打印出来的署名是用户自己的，不是「审查人」。

## 常见坑

- 不装配、直接拿两份大 prompt 全量套 → 规则封顶、意见跑偏，这正是装配器要解决的问题。
- **装配时手抖漏掉一个情形包** → 那一整包的硬伤全漏。实战教训：多甲方的件没装 S1，
  「各甲方不承担连带清偿责任」这条必补条款就没提出来。用 `--scan-input` 让程序替你兜底。
- **错别字只靠肉眼** → 四十页合同必漏。`typo.py` 一秒扫完，还直接给可落盘的 @修订。
- 扫描当判断用 → 弱线索只数词频，「像」不等于「是」；但**强触发（多甲方、村集体、中标通知书…）
  默认就该装上**，不装要写理由。
- 一条修订跑一条命令 → 最大的时间浪费，用 `--block --auto` 一次跑完。
- 忘了 `--start` → 时间线会从「现在」起算；用户说了收件时刻就按他说的填。
- 用了 `--auto` 就不看 `actions` → 自动降级的批注是占位话术，直接交付等于把机器口吻发给客户。
- 把相邻几处并成一个大替换 → 一条意见一条条目，要能和报告序号一一对上。
- 在两侧各留一份来件 → 交付件写回去时对不上，改哪份都不对。
- 体检 C0 挂了就手动改 XML 把它糊过去 → 下一份来件照挂。改脚本 + 跑自检，一次修干净。
- **忘了改 `配置.json` 就交付** → 客户拿到一份署名「审查人」的修订稿。
