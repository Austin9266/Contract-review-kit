# 落盘块格式、一键落盘用法与 C0–C7 体检

## 一、落盘块（你唯一要产出的机器可读物）

```
<<<落盘>>>
@修订 1 | 第7.2条
原文：甲方应在收到发票后15日内付款
改为：甲方应在收到发票且发票经审核无误后30日内付款
理由：付款起算点不明确，审核期未约定
@删除 2 | 第9.4条
原文：，并按日万分之五支付违约金
理由：同一违约行为重复约定违约金
@批注 3 | 第3.1条
锚点：甲方应在收到发票后15日内付款
批注：请确认审核时限。
理由：属商业判断，需经办人决策
@新增 4 | 第9条之后
锚点：本合同一式肆份，甲乙双方各执贰份。
正文：9.5 因不可抗力导致本合同无法履行的，双方互不承担违约责任。
理由：缺不可抗力条款
@删段 5 | 第11.3条
锚点：甲方有权索扣履约保证金
理由：全文未设履约保证金，该条无所依附
<<<落盘完>>>
```

| 类型 | 干什么 | 必填 |
|---|---|---|
| `@修订` | 把一小段原文改成另一段 | 原文、改为 |
| `@删除` | 把一小段原文整串删掉 | 原文 |
| `@批注` | 在某串原文上挂一条 Word 批注 | 锚点（或位置）、批注 |
| `@新增` | 在某一段之后整段新增 | 锚点、正文 |
| `@删段` | 整段删掉 | 锚点 |

头行：`@类型 序号 | 条款位置`。序号和位置都可省，但给了更好——位置用来在同一句话
全文出现多次时消歧。字段名固定：原文／改为／锚点／批注／正文／理由／第几处；
冒号全角半角都认，行首的 `-` `*` 列表符也认。

### 十条规矩

1. 「原文」「锚点」必须是来件里逐字照抄的一小段，标点一起抄。
2. 空格、全半角、弯直引号的差异程序会归一；但不许改字、不许省略、不许用「……」代替中间。
3. 「原文」不得跨自然段。一句里改两处就写两条。整段替换拆成「删段＋新增」。
4. 抄得越短越好定位，只要在该条款里唯一即可。
5. 「改为」写改完之后那一小段的完整文字。程序自己算最小改动，你不必只写变化的字——
   Word 里看到的会是「15 → 30」，不是整句划线重写。
6. 「批注」≤40 字，一条只讲一个问题；说理写在「理由」里，不进 Word。
7. 「正文」多段就分行写，程序按条款号开头判断分段。
8. 数字、金额、名称照抄来件写法。
9. 块里不写表格、不写 markdown、不加代码围栏、不写旁白。
10. 目录、页码、页眉页脚只批注不修订；表格内、图片内的问题不进落盘块，另列给人工。

### 程序会怎么对待你的文字

- 对得上 → 直接落；
- 只差空格/全半角 → 归一后按**来件里的原样**落（写进文件的是来件的字，不是你的字）；
- 差一两个字 → 相似度定位，标「请核对」；
- 差太多 → 「找不到」，给最像的几段候选；
- 抄错到「其实没有改动」 → 直接跳过并说明，不会塞一个空修订；
- 落在来件既有修订块里 → 拒绝叠改，那一条退回人工；
- 两条改到同一处 → 拦下，提示合并。

## 二、一键落盘 CLI（AI 自主执行的那条命令）

`contract-review-sop/scripts/oneshot.py`（＝落盘台的 `一键落盘.py`、contract-redline 的
`scripts/oneshot.py`，同一份代码）。落盘台界面上人能做的每件事，这里都有对应参数。

```bash
# 看来件情况，决定直落还是退回纯文字
python3 $S/oneshot.py --input 来件.docx --inspect --json -

# 试跑：只定位不写文件
python3 $S/oneshot.py --input 来件.docx --block 落盘块.txt --auto --dry-run --json -

# 自主跑：能自动收敛的自动收敛，收不住的进 needs_human
python3 $S/oneshot.py --input 来件.docx --block 落盘块.txt --auto \
  --start "2026-09-01T09:20" --json 报告.json --emit-block 实际落盘块.txt

# 把你的决定一次交回去
python3 $S/oneshot.py --input 来件.docx --block 落盘块.txt --auto --patch 决定.json --json -

# 查来件真实原文（抄错时用）
python3 $S/oneshot.py --input 来件.docx --search "履约保证金"
```

| 参数 | 说明 |
|---|---|
| `--block` | 落盘块：文件路径、`-`（读标准输入）或直接给整段文字 |
| `--auto` | 自主模式＝`--on-blocked note` ＋ `--auto-pick 0.9` |
| `--on-blocked note\|skip\|none` | 修订落在来件既有修订块上时：降级为批注／跳过／留着报给人（默认 none） |
| `--auto-pick 0.9` | 候选相似度达到该值且比第二名领先 0.08 以上时自动指认 |
| `--patch 决定.json` | uid → `{kind, src, dst, anchor, note, body, loc, occ, pick, skip}`，一个文件把所有决定交回去 |
| `--pick uid=段号[:起:止]` / `--skip uid` | patch 的命令行简写，可多次 |
| `--emit-block PATH` | 导出实际落盘用的落盘块（含 patch 与自动改动），留档或交给人在落盘台续做 |
| `--start` / `--end` | 时间线（北京时间钟面），默认起点＝此刻 |
| `--windows` / `--weekend` | 工作时段，默认取 `配置.json` 的「工作时段」、不落周末 |
| `--author` / `--initials` | 默认取 `配置.json` 的「署名」/「署名缩写」 |
| `--name` / `--outdir` | 默认「来件名（修订稿）」、来件所在文件夹 |
| `--strict` | 有任何存疑条目就停下不落盘（退出码 2） |
| `--quiet` | 只出 JSON（日志仍在 JSON 的 `log` 里） |
| `--json PATH\|-` | 完整报告；`-` 打到标准输出 |

**uid ＝落盘块里条目的先后顺序（1 起）**，与 `@修订` 后面那个可重复的序号无关。
退出码：0 正常（含"有条目没落但其余照落"）、1 硬失败（体检没过／没有可落条目）、2 `--strict` 拦下。

## 三、C0–C7 体检（任一 FAIL 都不许交付）

| | 检查什么 | 为什么 |
|---|---|---|
| C0 | 每个 XML 部件都能被完整解析、无悬空引用、本次新增修订 `w:id` 无重复 | 切坏 XML、删部件不清引用都会让 Word 报「文件损坏」 |
| C1 | 除 document/comments/rels/内容类型外，所有部件与来件**逐字节相同** | 样式、编号、页眉页脚、图片、字体一个都没动 |
| C2 | **拒绝全部修订后的正文 == 来件正文** | 有改动没被修订标记包住的话，Word 里看不出来，最阴 |
| C3 | 本次新增的修订与批注作者唯一、无 PENDING 残留 | 不出现第二作者 |
| C4 | 本次时间与 Word 同形（北京钟面+Z、秒为 00）、在工作时段内、单调不减 | 时间形态不对，或把北京时间当 UTC 存了 |
| C5 | 交付后缀 == 来件后缀 | .doc 进 .doc 出 |
| C6 | 每条批注都有锚点 | 否则批注存在但 Word 里看不见 |
| C7 | 来件既有的第三方修订/批注一条不少、一字未改 | 冒认别人的修改，比格式漂移严重得多 |

C2 挂＝有改动没被修订标记包住；C7 挂＝动到了别人的痕迹。**这两条一律不硬发**，
改交落盘块纯文字，由人在落盘台上手落。
