# 交叉引用判定规则（references/judgement-rules.md）

本文件定义审查合同交叉引用时的判定逻辑。脚本负责"定位"，本文件指导 agent 完成"判断"。

## 一、编区（scope）与语境判定

中文合同/招标文件常见编区：

| 编区类型 | 典型名称 | 编号特点 |
|---|---|---|
| 招标程序章节 | 第一章 招标公告 / 第二章 投标人须知 / 第三章 评标办法 / 第八章 投标文件格式 | 各章内部从 1 开始独立编号（如投标人须知 1.1~8.5） |
| 合同协议书 | 第一部分 合同协议书 | 通常无小数编号，用"一、二、三"或"第X条" |
| 通用合同条款 | 第二部分 通用合同条款 | 条号 1~24（如 18.1 竣工试验），体系固定 |
| 专用合同条款 | 第三部分 专用合同条款 | 与通用条款平行的编号体系，对通用条款做修改/补充，**编号与通用条款大量重复** |
| 技术规范 | 发包人要求 / 技术标准和要求 | 独立编号 |
| 附件 | 附件一/二/三… | 各自独立编号 |

### 语境判定优先级（同一编号出现在多个编区时）

对每一处引用，按以下顺序确定被引用条款所在的编区：

1. **显式限定语优先**：引用中带有限定语时，以限定语为准。
   - "本章第2.2款" → 当前章/当前部分
   - "专用合同条款第17.3.6条" → 专用合同条款
   - "通用条款第22.1.1款" → 通用合同条款
   - "第二章'投标人须知'第1.4.3项" → 第二章
   - "招标文件第五章" → 第五章
2. **无限定语时按就近原则**：引用目标默认在引用者**所在的同一编区**内。
   - 专用条款内写"按第15条执行"→ 指合同条款体系的第15条（通用条款第15条"变更"；专用条款对通用条款的引用惯例是指向通用条款编号）。
   - 投标人须知内写"本章第3.4.1项"→ 投标人须知 3.4.1。
3. **专用条款的特殊规则**：专用合同条款是对通用合同条款的修改补充，其内部引用裸编号（无"专用/通用"限定）时，**默认指向通用合同条款的同号条款**，这是工程合同（FIDIC 体系、住建部示范文本）的通行惯例。
4. **歧义标记**：当裸编号在两个以上编区都存在、且语义上都说得通时，标记为"歧义"，建议合同明确限定语。

## 二、四层核查清单

对每一处引用依次核查：

### 第 1 层：存在性
被引用编号在目标编区是否存在？
- 不存在 → 错误：悬空引用（常见于条款删改后引用未更新）。
- 例：引用"第 18.9 款"但合同删除了竣工后试验条款。

### 第 2 层：层级一致性
引用单位（条/款/项/目）与目标编号的层级是否吻合？
- 通行惯例（示范文本 GF-2020-0216 等）：
  - "条" = 一级编号（第 18 条）
  - "款" = 二级编号（第 18.1 款）
  - "项" = 三级编号（第 18.1.1 项）
  - "目" = 四级编号（第 1.1.1.1 目）
- 但实践中**款/项/条混用极常见**（如把 17.3.6 叫"条"）。规则：
  - 编号层级与称谓明显错位两级以上（如"第 18.1.1.2 款"）→ 标记"称谓存疑"。
  - 一级编号被称"款"（如"第 18 款"）→ 标记"称谓存疑"。
  - 其他款/项混用 → 仅作提示，不算错误。

### 第 3 层：语义匹配（核心）
读出被引用条款的标题与正文，判断其内容是否与引用语境所期待的事项一致：
- 引用语境期待的事项（如"根据第 18.1 款要求进行的试验"→ 期待"竣工试验"）；
- 被引用条款实际说的事（如 18.1 实际为"竣工试验"→ 匹配）。
- 不匹配 → 错误：错引（可能作者想引用的是邻近编号，如 18.9 而非 18.1）。
- 特别注意**责任方向**：如引用条款规定的是"发包人赔偿承包人"，但引用语境是"承包人保障发包人"，方向相反则疑似错引。

### 第 4 层：结构合理性
- **AB 选项条款**：示范文本中并列的"（A）（B）"备选条款（如 4.11(A)/4.11(B)、18.9(A)/18.9(B)），合同定稿应二选一。若引用指向已被删除或未明确选择的选项 → 标记。
- **循环引用**：A 引 B、B 又引 A 且无语义出口 → 标记。
- **自引用**：条款引用自身 → 标记。
- **引用链断裂**："按第 5.5 款提交文件后……"而 5.5 款又被专用条款删除 → 按第 1 层处理。

## 三、发现分级与写作口径

> 本节与第六节的贯穿例子（通用条款 7.3.4 / 专用条款 6.3、9.3）按公开示范文本的编号体例自行构造，
> 具体数字一律占位，非任何具体项目文件。

本节决定报告好不好用。定位和判断做对了，但话说得绕、把结论埋在推理后面，使用者仍然要重读一遍原文——等于没省事。

### 3.1 分级 = 对方要做什么

| 级别 | 判断标准 | 对方的动作 | 批注动词 |
|---|---|---|---|
| 错误 | 引用目标不存在、语义明显不符、责任方向相反；两条实质冲突或位阶不明，说不清按哪一条走 | 必须改 | 建议改为…／建议删除…／建议补解释顺序条款 |
| 警告 | 已能说清按哪一条走，只缺一个可补的要素（起算日、主体、口径）；AB 选项未定 | 需确认或补明确 | 请核实…／请明确… |
| 提示 | 不影响权利义务，只是体例、称谓、可读性 | 可不改 | 建议统一… |

**定级依据是"改与不改的结果是否确定"，不是"能不能在别处找到相关条款"。** 在别处发现可能覆盖同一事项的条款时，先做位阶判断，再定级：

1. **位阶明确 + 只缺一个可补的要素** → 警告。位阶明确指：合同有明文的解释顺序条款（协议书 > 中标通知书 > 专用条款 > 通用条款……），或该关系本身是体系性的（专用条款系对通用条款的修改补充、特别约定优于一般约定）。此时若能说清"按哪一条走"，只是起算日、责任主体、金额口径之类要素没写明，用"请核实 X；如按 X，请明确 Y"的双段式，并在依据里点明所依赖的位阶。
2. **位阶明确但两条实质冲突**，不是补一个要素能解决的 → 仍是错误，直接给出应保留哪一条。
3. **位阶不明** → 错误，且不得因"别处可能已有约定"而降级。位阶不明的典型情形：同一编区内两条并行约定同一事项；跨编区而合同未约定解释顺序；附件、技术规范与正文的效力关系未约定；专用条款既未声明修改也未声明保留通用条款同号条款。此时批注要求补解释顺序条款或统一表述，而不是让对方自己猜。

不确定 ≠ 降级。只有在"能说清按哪一条走"的前提下才降为警告；说不清按哪一条走，本身就是要写进报告的问题。"可能是作者本意"同理——本意不明而后果确定的（悬空、责任方向相反），仍判错误。

### 3.2 一条发现只讲一个问题

同一处引用既有实质问题（悬空、错引、语义不匹配）又有形式问题（缺"款/项"单位、称谓错位）时：

- 立条只用实质问题；标题不得写成"未加单位，且内容对应错误"这种并列句；
- 形式问题一律并入报告第三节的批量表格，不单独占条。

纯形式问题从不单独立条，全部进批量表格。

### 3.3 标题写后果，不写现象

标题 ≤ 25 字，说清"哪个条款、什么权利义务落空"，不复述引用编号之间的关系。

- 差：`通用条款 7.3.4 引用"专用合同条款6.3"——未加"第X款"单位，且专用条款 6.3 内容对应错误`
- 好：`通用条款 7.3.4：暂停履约的 【】天起算日无处落地`

### 3.4 批注建议是交付核心

每条发现的第一行，必须是可以直接粘进 Word 批注框的一句话（可交由 contract-redline 技能落盘）：

- 动词开头：请核实／请明确／建议改为／建议删除／建议补充；
- ≤ 2 句、≤ 60 字；
- 必须落到具体：具体的替代条号、具体缺失的要素（起算日、责任主体、金额口径……）；
- 不复述推理，不出现"悬空引用""语义不匹配"这类分析术语——那些属于"依据"。

真实批注口径范例：

> 请核实是否为专用条款 9.3 约定的"支付节点目标完成后的【】日内支付"；如按 9.3 约定，请明确该 【】天的起算日。

### 3.5 依据从简

"依据"最多 3 行、每行 1 句，只回答三件事：目标条款实际写了什么、缺了什么、可能的正确目标在哪。原文摘录只取足以辨认的半句，不整段粘贴，不重复标题已说过的话。

## 四、样例库（按《标准施工招标文件》的公开体例构造，非任何具体项目文件）

1. **定义条款引用**：通用条款 1.1.4.8 "竣工试验：是指……根据第 18.1 款要求进行的试验"——18.1 恰为"竣工试验"→ 正确。
2. **多编区歧义**：专用条款 10.2.10 引用"第 10.1.3 项"，通用条款 10.1.3 是"发包人负责赔偿第三者人身伤亡"，而专用条款语境是"承包人保障发包人免受赔偿"——责任方向相反，**疑似错引**（可能应引用 10.2.9"承包人赔偿第三者责任"）。
3. **跨章引用**：评标办法中"符合第二章'投标人须知'第 1.4.1 项规定"——限定语明确指向第二章 → 在第二章内核对 1.4.1 内容。
4. **称谓混用**："进度款按形象进度支付，具体节点见专用合同条款第 17.3.6 条"——17.3.6 是三级编号却称"条"→ 警告。
5. **专用条款新增条款**："增加第 15.7 款"——通用条款 15 条下原无 15.7，此为专用条款增设 → 正确（增设类引用属正常）。

## 五、输出报告格式

四节结构，重要的在前，噪音在后。

### 第一节 结论速览

一句话总体判断（例："共 132 处引用，需处理 9 处，其中 3 处影响付款与工期"），随后给需处理项一览表：

| # | 位置 | 级别 | 一句话问题 | 建议动作 |
|---|---|---|---|---|
| 1 | 通用条款 7.3.4 | 错误 | 暂停履约的 【】天起算日无处落地 | 请核实并明确起算日 |

### 第二节 逐条发现（只列错误与警告）

每条固定四行，顺序不变：

```
### N ｜〔级别〕标题（写后果，≤25 字）
**批注**：<可直接粘贴的一句话，见 3.4>
**位置**：<编区 + 条号>（第 X 行）｜引用原文："……"
**依据**：<≤3 行>
```

示例：

```
### 1 ｜〔警告〕通用条款 7.3.4：暂停履约的 【】天起算日无处落地
**批注**：请核实是否为专用条款 9.3 约定的"支付节点目标完成后的【】日内支付"；如按 9.3 约定，请明确该 【】天的起算日。
**位置**：通用合同条款 7.3.4｜引用原文："在专用合同条款6.3中约定的支付之日起【】天后仍未收到……"
**依据**：专用条款 6.3"支付酬金"只规定预付款与支付分解表，未出现"支付之日"；全文唯一的付款时点在专用条款 9.3，且专用条款优于通用条款，可据以补明起算日。
```

### 第三节 称谓与格式（批量一表带过）

所有"提示"级发现与形式问题合并成一张表，不展开说明：

| 位置 | 引用原文 | 问题 | 建议 |
|---|---|---|---|

### 第四节 核对无误

只列条号，一行一组，不展开内容。

结尾用一句话给出"建议全文统一的编号称谓规则"，不超过 3 行。

### 篇幅红线

- 单条发现不超过 6 行；
- 核对无误的引用绝不逐条展开；
- 报告里不出现审查过程叙述（"我先运行脚本……"）。

## 六、反例对照

同一处问题的两种写法：

**改前**（结论被埋在三段推理之后，且把形式问题和实质问题并列成标题）：

> 3. 通用条款 7.3.4 引用"专用合同条款6.3"——未加"第X款"单位，且专用条款 6.3 内容对应错误
> - 通用条款 7.3.4："咨询人在专用合同条款6.3中约定的支付之日起【】天后仍未收到委托人按本合同约定应付的款项……"
> - 专用合同条款 6.3 是"支付酬金"，其下 6.3.1 预付款、6.3.2 咨询服务费的支付（支付分解表），均未约定具体的"支付之日"（只在专用条款 9.3 咨询费用里写了"支付节点目标完成后的【】日内支付"）。
> - 引用未写"款/项"，且指向的 6.3 本身并未给出"支付之日"的明确约定，属于悬空引用/语义不匹配。

**改后**（后果先行、批注可直接落盘、形式问题下沉到第三节表格）：

> ### 3 ｜〔警告〕通用条款 7.3.4：暂停履约的 【】天起算日无处落地
> **批注**：请核实是否为专用条款 9.3 约定的"支付节点目标完成后的【】日内支付"；如按 9.3 约定，请明确该 【】天的起算日。
> **位置**：通用合同条款 7.3.4｜引用原文："在专用合同条款6.3中约定的支付之日起【】天后仍未收到……"
> **依据**：专用条款 6.3"支付酬金"只有预付款与支付分解表，无"支付之日"；付款时点见专用条款 9.3，专用优于通用，可据以补明起算日。
