# 合同审查工具包 · contract-review-kit

> A Chinese-language contract review toolkit for Claude Code: 138 rule cards assembled
> per-document, plus a deterministic engine that writes the conclusions into Word as real
> tracked changes and comments, with an 8-point pre-delivery integrity check.
> MIT licensed. Ships with **no** client data, firm identity, or industry-specific content.

合同审查，从判断到交付：AI 读完合同产出的是文字，
文字如何变成 Word 上的修订与批注，交给代码！不靠大模型，就没有幻觉，不会把文件乱改一通！


```
来件
 └─ 0 来件体检        ← 决定 AI 直接改文件，还是只交纯文字让人来落
 └─ 1 认件与装配      ← 138 张规则卡按情况装，不全量套
 └─ 2 机械前置        ← 交叉引用 + 错别字衍字 + 确定性九查，不用脑的先做完
 └─ 3 判断（两遍法）  ← 先裸审，再拿清单查漏；只做加法
 └─ 4 落盘块          ← AI 唯一要产出的机器可读物
 └─ 5 落盘            ← 一条命令，约 1 秒：定位、署名、时间线、打包
 └─ 6 自主收敛        ← 落不了刀的自动降级，收不住的交回人工
 └─ 7 交付            ← C0–C7 体检全过才出文件
```

## 先做两件事

### 1. 填配置（**必做**，两分钟）

打开根目录的 `配置.json`，至少改这两行：

```json
"署名": "某某律所 张三",
"署名缩写": "张",
```

这会写进交付件的每一处修订与批注。不改，客户拿到的就是一份署名「审查人」的修订稿。

顺带把「工作时段」改成你自己的作息（默认 `09:00-18:00`，有午休就写
`09:00-12:00,14:00-18:00`）——修订与批注的时间戳会落在这个区间里。

**署名、缩写、工作时段只有这一个来源**：命令行脚本和落盘台页面都从这里读，
页面上不再自带任何人的默认值。

```bash
python3 skills/contract-review-sop/scripts/config.py
```

跑一下能看到当前生效的配置、以及它是从哪个文件读到的。

### 2. 装技能

```bash
bash 安装.sh
```

默认装到 `~/.claude/skills/`，并在 `~/.contract-review/` 放一份配置。
想装别处：`bash 安装.sh /你的/skills`。

装完在 Claude 里说「审一下这份合同」并附上 .docx，就会走完整条流水线。

## 环境

- **Python 3**（macOS 自带；没有就 `xcode-select --install`）。落盘全程只用标准库。
- **LibreOffice**（可选）：只有来件是 `.doc`（旧二进制格式）时才需要，用来进出格式转换。
  `--inspect` 会告诉你这台机器有没有。来件是 `.docx` 就完全用不到。

## 三个技能，一大两小

| 技能 | 干什么 | 什么时候自己会被叫起来 |
|---|---|---|
| **contract-review-sop** | **总编排**。0–7 步全流程，自带规则库与全部程序，不依赖别的技能 | 发来 .doc/.docx 说「审一下／帮我改／出修订稿」 |
| contract-redline | 把已定好的意见落成 Word 修订与批注 | 说「按这份意见改文件／出修订稿／redline」 |
| contract-cross-reference-checker | 交叉引用专项核查，出分级报告 | 说「核对交叉引用／第X.X款引用对不对」 |

主技能把后两个的能力都内置了一份，所以**日常审查只装 contract-review-sop 就能从头做到尾**。
另外两个是单独拿出来用的入口。

## 两个界面（不装技能也能用）

### 工作台 —— 生成审查 prompt

`工作台/审查工作台.html`，双击用浏览器打开，不需要联网、不需要服务器。

左栏选：合同还是文书、我方是谁、站哪一方、我方模板还是对方模板、什么类型、涉及哪些情形；
右栏实时生成这次专用的审查 prompt，复制去喂任何模型（Claude、GPT、Kimi 都行）。

138 张规则卡按「通用核 ＋ 情形包 ＋ 类型包」装配——**只把用得上的带进场**。
全量套用会让模型在不适用的条目上浪费判断力，还会把不该提的意见提出来。

卡片能就地改、能加，改完存成 `rules.js` 放在同目录，页面下次自动读它。

命令行等价物是 `skills/contract-review-sop/scripts/assemble.py`，输出与页面逐字一致。

### 落盘台 —— 把 AI 的纯文本落成 Word

`落盘台/启动.command`，双击打开本地页面（127.0.0.1，文件不出本机）。

选来件 → 把 AI 产出的《落盘块》整段粘进去 → 试跑 → 正式落盘。
逐条能看状态、能指认段落、能把修订改成批注、能就地改原文、能跳过。

无界面版是 `落盘台/一键落盘.py`，同一份代码，给 AI 或脚本用：

```bash
python3 落盘台/一键落盘.py --input 来件.docx --block 落盘块.txt --auto --json 报告.json
```

详见 `落盘台/说明.md`。

## 落盘块长什么样

AI 唯一要产出的机器可读物。人能读，落盘台也能吃。

```
<<<落盘>>>
@修订 1 | 第7.2条
原文：甲方应在收到发票后15日内付款
改为：甲方应在收到发票且发票经审核无误后30日内付款
理由：付款起算点不明确，审核期未约定
@批注 2 | 第3.1条
锚点：甲方应在收到发票后15日内付款
批注：请确认审核时限。
理由：属商业判断，需经办人决策
<<<落盘完>>>
```

五种条目：`@修订` `@删除` `@批注` `@新增` `@删段`。
完整规范见 `落盘台/落盘块格式.md`。

## 规则卡：这套东西真正的价值，也是你要长期养的部分

出厂带 138 张卡，分三层：

| 层 | 数量 | 什么时候装 |
|---|---|---|
| **CORE 通用核** | 15 张 | 无条件适用。金额验算、附件三对照、份数、主体名称、日期推演、法规真伪、交叉引用、管辖…… |
| **S 情形包** | 8 个 | 按交易实际装：多主体、框架两层、补充变更终止、涉政府或村集体、涉招投标、对方模板、涉外币、涉不动产 |
| **T 类型包** | 10 个（最多装一个） | 按合同类型装：工程施工、设备采购、技术服务、租赁、投资框架、金融借款、公司治理、函件承诺、安全生产、结算变更 |

**这 138 张是通用合同问题，不含任何行业专属知识。** 这是有意的——一个装满别人行业规则的库，
对你只是噪音。你这行的门道（医药的临床试验协议、互联网的数据处理协议、影视的版权许可、
外贸的贸易术语……）需要你自己往里加。

### 怎么加

规则库就是一个 JSON 文件：`skills/contract-review-sop/rules/规则库.json`。
**改完立刻生效**，不用重启、不用重新装技能。

一张卡的关键是三个字段：

- `sig` —— **这个问题在文本里长什么样**。写具体，最好直接是能被眼睛扫到的原句片段。
- `ask` —— 命中时批注实际怎么写。≤40 字，一条一个问题。
- `fail` —— **什么情况下这条不适用**。⚠️ 最容易偷懒也最贵的一个字段：
  没有例外的规则会被照套，然后提出错误意见。

改完跑一次体检：

```bash
python3 skills/contract-review-sop/scripts/查规则库.py
```

它查重号、查 id 与包对不上、查孤儿卡、查必填字段为空。**有 ❌ 就别用**——
最隐蔽的坏法是卡号重复，装配时静默丢卡，你收不到任何报错。

### 用自己的稿子把它养起来（推荐）

这套卡本来就是这么攒出来的：**不是坐着想规则，是回头看自己改过的合同。**

攒够十来份改过的合同（落盘块本身就是现成的清单），把它们连同规则库一起丢给 Claude：

> 这是我最近改过的 8 份合同的落盘块。对照 `rules/规则库.json`，
> 告诉我：（1）哪些问题现有卡片没覆盖，建议加成什么卡；
> （2）哪些卡片这几次没命中或误报了，`when`/`sig`/`fail` 该怎么调。
> 加卡按 CLAUDE.md 1.3 的字段要求写，改完跑 `查规则库.py`。

两条经验：

- **误报优先改 `fail`，不要直接删卡。** 删掉就再也想不起来了；写进 `fail`
  反而让模型学会了分辨。
- **示例句写成"同形但虚构"的版本。** `sig` 要的是"这个问题长什么样"，不是"原文是什么"——
  句式关键词照旧，主体名去掉，具体数字换成 `X`/`N`/`【】`。规则库是会被分发的文件，
  直接粘来件原句等于把客户的合同条款一起发出去了。

完整的字段说明、加类型包的步骤、同步办法，都在 **`CLAUDE.md`**。
那份文件也是 Claude 在这个目录里工作时会读的，所以你直接说
「帮我加一张卡」「这条老误报，改一下」，它知道该怎么办、改完该跑什么。

## 交付前的体检（C0–C7）

**任一项 FAIL 就不出文件**，来件本身一个字没动。

| | 查什么 |
|---|---|
| C0 | 所有 XML 部件能解析、无悬空引用、修订 id 唯一 |
| C1 | 正文以外的部件零改动、无缺失、无意外新增 |
| C2 | **拒绝全部修订后，正文 == 来件正文**（有改动没被修订标记包住就挂） |
| C3 | 本次署名唯一、无 PENDING 占位残留 |
| C4 | 时间与 Word 同形（北京钟面 + Z、秒为 00）、落在工作时段内 |
| C5 | 交付后缀 == 来件后缀（.doc 进 .doc 出） |
| C6 | 批注都有锚点 |
| C7 | **来件既有的第三方修订/批注一个字没动** |

C2 和 C7 挂了一律不硬发——那是"改坏了别人的文件"和"把别人的修改冒认成自己的"。

## 什么时候不由 AI 改文件

命中任一条 → AI 只交落盘块纯文字，人在落盘台上手落：

1. 来件是 `.doc` 而两侧都没有 LibreOffice；
2. 一次跑完并自动收敛后，仍有 1/3 以上条目落不上；
3. C0–C7 任一 FAIL；
4. 过半段落长在表格里；
5. 用户说了只要文字。

来件本身带着客户或对方律师的修订**不是**退回理由——脚本只叠加不改动，C7 会逐条核对。

## 几句实话

- **规则不是一次全上。** 装配宁滥勿缺，但也别全量套——每张卡都带「例外」，写明什么情况下
  这条不适用、照套会怎么误导。装了的也要逐条问「这份文件是不是这条说的那种情况」。
- **错别字和交叉引用是默认动作**，每件必跑机械扫描。肉眼在四十页合同上必漏。
- **慢的从来不是脚本，是来回次数。** 整张清单一次跑完，别一条修订跑一条命令。
- **拿不准就跳过并说明**，不猜着往客户文件里写。
- 这套东西替你把手不抖的部分做了，**判断仍然是你的**。交付前自己读一遍。

## 免责与边界

- **这不是法律意见，也不替代律师判断。** 它替你做的是"手不抖"的部分：机械扫描、准确落盘、
  交付前体检。审查结论、风险取舍、要不要提某条意见，仍然是执业判断。**交付前自己通读一遍。**
- **规则卡会误报，也会漏报。** 每张卡都带「例外」正是因为规则本身有边界；照单全收会出错。
- **合同与客户信息的保密是使用者的责任。** 这个工具在本机运行，不上传任何文件；
  但你如果把来件内容写进规则卡再分享出去，那是你自己泄的密——所以有 `脱敏自检.py`。
- **法规引用需自行核实。** 卡片里提到的法条会随修法变化；模型也可能记错。
  涉及法条编号、时效、机构全称的，一律实查后再写。

## 发出去之前：脱敏自检

你往规则卡、示例、界面预填值里写过自己的东西之后，发给别人之前跑一次：

```bash
python3 脱敏自检.py
```

它按**特征**找，不靠记忆，九类：真实金额（千分位、多位小数，**以及中文数字与大写写法**）、预填值与代码兜底常量里的人名·日期·作息时段、写死的日期、机构名与人名（含从词表
派生的**单姓**）、行业专属词、私人路径（`/Users/你的用户名`）、日志和 `__pycache__` 这类
运行产物、**引号里又长又带具体数字的片段**（多半是从真实来件抄下来的条款原文），
以及**指向具体乡镇区县或园区的地名**——通用工具包里没有任何理由留着真实地名。

它也扫自己：检测器把自己排除在外，是这类工具最典型的坏法（只有顶部
`# <<<SELF-EXEMPT` 到 `# SELF-EXEMPT>>>` 之间的说明与词表不参与自查）。

**先建一份 `脱敏词表.local.txt`**（一行一条，`#` 开头是注释），把你的机构名、同事名、
常合作的客户名写进去，自检就会替你盯着这些词，中文全名还会自动派生单姓一起查
（真实泄露常常只剩一个姓）。

```
某某律所            ← 你的机构
李四                ← 你和同事
某某集团            ← 常合作的客户
```

**别把这些词写进 `脱敏自检.py`**：那个文件是要随包分发的，写进去等于把刚洗掉的东西又发出去
一遍，而且它落在自查豁免区里、脚本永远查不到自己那一行。`.gitignore` 挡着 `*.local.txt`，
自检还会主动核对这一点——挡不住就直接报 ❌。

没有这份词表时自检会在抬头提醒你，此时 L4 只挡机构口吻词和带机构后缀的专名，挡不住你自己的名字。

L8 是靠"引号里既长又带数字"来猜的，必然会误伤两类正常内容：公开范本里的条号、你自己编的
示例句。确认没问题的整行加进 `脱敏白名单.txt` 即可放行。
**但别拿白名单躲事**——如果那句话真是从客户合同里抄来的，该改的是原文。
