# 合同交叉引用审查（Contract Cross-Reference Checker）

## Overview

审查合同/招标文件中"第X.Y款""第X条"等交叉引用是否指向正确的条款。典型问题：引用编号不存在（悬空引用）、通用条款与专用条款编号重复导致的歧义与错引、款/项/条称谓错位、语义不匹配（如引用条款说的不是引用语境所称的事）、责任方向相反。

## 工作流程

### 第 1 步：提取与索引（脚本机械化完成）

运行提取脚本，得到编区结构、条号索引、引用清单三份数据：

```bash
python3 scripts/extract_index.py <合同文件.docx|.txt> -o /tmp/xref_index.json
```

输出 JSON 包含：
- `scopes`：编区列表（行号 + 名称），如"第二章 投标人须知""第二部分 通用合同条款""第三部分 专用合同条款"；
- `index`：每个条号候选（行号、所在编区、编号、标题行）；
- `references`：每处交叉引用（行号、所在编区、引用编号、单位[条/款/项/目]、限定语[如"本章""专用合同条款"]、上下文）。

脚本只做定位不做判断。大文件（引用 >100 处）时用 `--refs-only` 先看引用清单，再按需用 Grep/Read 回到原文核对目标条款。

### 第 2 步：加载判定规则

读取 `references/judgement-rules.md`，其中定义了：
- **语境判定优先级**：显式限定语 > 同编区就近 > 专用条款裸编号默认指向通用条款同号条款；
- **四层核查清单**：存在性 → 层级称谓一致性 → 语义匹配（核心）→ 结构合理性（AB选项条款、循环引用、自引用）；
- **发现分级**：错误 / 警告 / 提示；
- **样例库**：按《标准施工招标文件》公开体例构造的典型正确/错误引用样例。

### 第 3 步：逐条核查

对 references 清单中的每一处引用：

1. 按语境判定规则确定目标编区（同一编号在通用/专用条款都存在时尤其关键）；
2. 在 index 中定位目标条号，不存在则回到原合同全文搜索确认（脚本可能漏识别非规范格式的条号行，宁可回到原文验证也不轻易报"不存在"）；
3. 用 Read 读取目标条款正文（按行号），判断其内容与引用语境是否匹配；
4. 按判定规则定级（错误＝必须改／警告＝需核实、明确／提示＝可不改），并当场写下那句可直接落盘的批注建议——不要留到最后统一措辞。

引用数量大时优先核查高风险引用：
- 专用条款中引用通用条款编号的（错引高发区）；
- 跨章引用（如评标办法引用投标人须知）；
- 定义条款中的引用（1.1 节，定义错了影响全文）；
- 涉及金额、期限、责任承担的引用。

### 第 4 步：输出审查报告

报告的目的是让审阅人**不用重读一遍合同就能决定改什么**。写作口径与分级见 references/judgement-rules.md 第三节，四节结构与逐条格式见第五节，反例对照见第六节——写报告前必须重读这三节。

三条硬约束：

1. **结论先行**：每条发现的标题写"什么权利义务落空"（≤25 字），不写"引用了 X 但 X 内容不对"；推理放"依据"，且不超过 3 行。
2. **第一行是可直接落盘的批注**：动词开头（请核实／请明确／建议改为），≤2 句，必须给出具体的替代条号或具体缺失要素，可交由 contract-redline 技能写入 Word 批注。
3. **一条只讲一个问题**：实质问题立条，称谓／单位／体例等形式问题批量下沉到第三节表格，不与实质问题并列写进标题。

**定级前先判位阶**：在别处发现可能覆盖同一事项的条款时，只有当解释顺序清楚（合同有解释顺序条款，或专用优于通用、特别优于一般这类体系性关系）、且只缺起算日/主体/口径之类可补要素时，才降为"警告"用"请核实"的口径；位阶不明或两条实质冲突的，仍是"错误"，并在批注里要求补解释顺序条款或直接统一表述。详见判定规则第 3.1 节。

报告写入文件（如 `交叉引用审查报告.md`）并用 present_files 交付；对话中只复述第一节的结论速览，不重复正文。

## Resources

### scripts/extract_index.py

合同交叉引用提取脚本（纯标准库，无第三方依赖）。从 .docx/.txt 提取编区结构、条号索引、交叉引用清单，输出 JSON。支持 `--refs-only` / `--index-only` 参数。内置 docx 段落抽取、目录行过滤、中文数字章节识别。

### references/judgement-rules.md

判定规则手册：编区类型表、语境判定优先级（解决通用/专用条款同号歧义的核心规则）、四层核查清单、发现分级与写作口径（第三节，决定报告好不好读）、样例库、四节报告格式与篇幅红线（第五节）、反例对照（第六节）。执行语义核查前必须加载，写报告前重读第三、五、六节。
