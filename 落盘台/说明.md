# 落盘台

把 AI 写的《落盘块》文字，落成来件 Word 上真正的修订与批注。

审查判断是一回事，把判断写进 Word 是另一回事。后者出错的方式很固定：改到了不该改的地方、
署名和时间是默认值或 UTC、把别人的修订冒认成自己的、.doc 交回去变成了 .docx。
所以这里的核心不是"会改"，而是**只改该改的地方 ＋ 交付前逐项体检，不过关就不出文件**。

定位、收窄修订范围、算第几处、署名、时间线、打包、C0–C7 体检，全是确定性代码，几秒钟跑完。

---

## 先做一件事：填署名

工具包根目录的 `配置.json`，把「署名」「署名缩写」改成你自己的。这两项会写进交付件的
每一处修订与批注——不改，客户拿到的就是一份署名「审查人」的修订稿。

```bash
python3 config.py        # 看当前生效的配置与它是从哪读到的
```

## 怎么用（界面版）

1. 双击 `启动.command`。浏览器自动打开本地页面（127.0.0.1，只跑在这台机器上，文件不出本机）。
   头一回被 macOS 拦下：右键 → 打开 → 再点「打开」。终端窗口关掉，服务就停。
2. 选来件（.doc / .docx 都行，也可以直接把文件拖进页面）。
3. 左栏确认署名、时间线、交付文件名。时间线起点填「客户把文件发给你的那一刻」。
4. 把审查报告第六项 `<<<落盘>>> … <<<落盘完>>>` 整段粘进右边，点「解析并定位」。
5. 逐条看状态：
   - **命中** —— 不用管。
   - **请核对** —— 原文与来件对不上，程序按相似度定了位。点开看预览，不对就指认或跳过。
   - **要指认** —— 同样的文字全文出现多处。点候选里的「就是这一处」。
   - **找不到** —— 搜关键词自己挂，或「跳过这一条」留给人工。

   每条点开都有三个按钮：
   - **改这一条** —— 就地改类型和文字。AI 写成修订、你看了想改成批注（或反过来），
     在这里换个类型即可：换成「批注」时锚点会自动填上原来的原文，你补一句批注文字就行。
     原文抄漏了一两个字，也在这里补，保存后立刻重新定位。
   - **改成批注** —— 上面那件事的快捷键。
   - **跳过这一条** —— 留给人工，不进文件。

   行号旁边的 `#1 #2` 是条目编号（落盘块里的先后顺序），和 `一键落盘.py` 的 `--pick/--skip`
   用的是同一套号。改完想留档或贴回报告的，点「导出改过的落盘块」。
6. 先「试跑」（不写任何文件），全绿了再「正式落盘」。
7. 交付文件默认存回来件所在文件夹；运行日志在 `日志/` 下，一次一份。

体检任何一项 FAIL 就不出文件。这时候来件本身一个字也没动过——中间产物都在系统临时目录里。

## 它替你处理掉的那些坑

- **空格、全角半角、弯直引号对不上**：归一化之后再定位，AI 抄原文时的这类差异不再是问题。
- **AI 抄漏一两个字**：相似度定位 + 候选段落，实在不行人工点一下。
  抄错到「其实没有改动」的，直接标出来并跳过，不会往文件里塞一个空修订。
- **同一句话全文出现好几次**：按条款号和文档顺序消歧；仍然拿不准就让你指认，绝不猜。
- **「第几处」会随落盘过程变化**：前一条修订把那段原文包进 `<w:del>` 之后，后面的条目就检索不到它了。
  程序按引擎的真实执行顺序模拟推算，并逐条回验锚定串确实落在预期位置。
- **修订范围过大**：把原文与改为的公共前后缀剥掉，只把真正变了的那几个字包进修订。
  Word 里看到的是「15 → 30」，不是整句划线重写。
- **插入文字的排版不像来件**：按来件「数字与汉字之间写不写空格」的习惯，自动对齐插入文字的写法。
- **改到同一处**：两条条目落在同一段文字上会被拦下，提示合并。
- **别人的痕迹**：来件已有的修订与批注保留署名、时间、内容，本次痕迹只叠加；C7 逐条核对。

## 目录

```
落盘台/
  启动.command     双击启动
  server.py        本地服务（只用标准库）
  ui.html          界面
  一键落盘.py      无界面版：一条命令跑完，给 AI 或脚本用
  config.py        读工具包根目录的 配置.json（署名、时段、交付后缀）
  核心/parser.py   落盘块 → 结构化条目（宽进：容错围栏、全角冒号、引号、软换行）
  核心/locator.py  归一化定位、相似度候选、收窄修订范围、排版习惯
  核心/planner.py  条目 × 来件 → 逐条定位结果 + 引擎吃的 plan.json
  引擎/            contract-redline 技能的脚本副本，一个字没改
  日志/            每次运行一份（首次运行时自动创建）
```

中间产物（解包目录、plan.json、打包结果）在系统临时目录下，只留最近 20 次。

## 无界面版：一键落盘（给 AI 用）

`一键落盘.py` 就是这个程序去掉界面的样子——同样的解析、定位、署名、体检，一个进程跑完，
.docx 约 1 秒。AI 审完直接跑它，不必再麻烦你：

```bash
python3 一键落盘.py --input 来件.docx --inspect --json -
```

```bash
python3 一键落盘.py --input 来件.docx --block 落盘块.txt --dry-run --json -
```

```bash
python3 一键落盘.py --input 来件.docx --block 落盘块.txt --auto --start "2026-09-01T09:20" --json 报告.json
```

```bash
python3 一键落盘.py --input 来件.docx --search "履约保证金"
```

加 `--auto`，它还会自己收敛：修订落在别人的修订块上（下不了刀）的自动降级为批注、
候选相似度 ≥0.9 且明显领先的自动指认；仍收不住的写进 JSON 的 `needs_human`，
AI 看完候选段落用一个 `--patch` 文件把决定一次交回去（改口径、改原文、指认、跳过）——
就是你在界面上点的那几个动作。**体检不过一样不出文件。**

什么时候仍然由你来落：来件是 .doc 而本机没装 LibreOffice、体检 C2/C7 挂了、
落不上的条目超过三分之一、过半段落长在表格里——这几种情况 AI 只交落盘块纯文字，你在这里上手落。

## 与 contract-redline 技能的关系

`引擎/` 就是那个技能的 `scripts/`，原样复制过来的。判断标准没变、体检标准没变、
写进文件的东西一模一样——变的只是「谁来写 plan、谁来试错」。

技能留着做兜底：程序处理不了的疑难件（表格里的修订、要整体重排的、来件结构古怪的），
仍然可以让 AI 走单步路。

引擎、核心、一键落盘都以**这个文件夹为准**，改完往两个技能各推一份（技能是分发副本）。
改过引擎之后先跑自检：

```bash
python3 ../skills/contract-review-sop/scripts/自检.py 某份真实来件.docx
```

它会造出「没有 commentsExtensible」「没有 people」「整份来件一条批注都没有」等变体，
把平时跑不到的「新建部件」路径都走一遍，五个变体全 PASS 再推。

```bash
bash 同步到技能.sh
```

## 出问题时

- 页面打不开 / 端口被占：`LUOPAN_PORT=8790 python3 server.py`
- 来件是 .doc 但转不了：本机要装 LibreOffice；实在不行先在 Word 里另存为 .docx。
- 体检 FAIL：看日志里 FAIL 那一行。C2 挂了说明有改动没被修订标记包住，C7 挂了说明动到了别人的痕迹——
  这两条都别硬发，回去查清楚。
- 交付件署名不对：`python3 config.py` 看它读到的是哪个 `配置.json`。
